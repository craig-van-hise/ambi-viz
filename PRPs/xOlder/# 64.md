# PRP #64: Sphere Deformation Exposed Controls & UI Swapping

## Objective
Implement a comprehensive set of exposed controls for the Legacy Sphere Deformation visualization mode, mirroring the interactivity of the volumetric ray-marching method. Crucially, the UI must automatically swap between the Volumetric control set and the Sphere Deformation control set based on the currently active visualization mode. You must follow a strict Test-Driven Development (TDD) methodology. 

## Strict TDD Rules
1. **Write Tests First:** Before implementing any feature code in a phase, write the corresponding unit tests (e.g., in `AmbiScene.test.ts` or component tests).
2. **Run and Fail:** Run the tests to ensure they fail.
3. **Implement:** Write the minimum code necessary to pass the tests.
4. **Pass and Refactor:** Run the tests to ensure they pass. Refactor if necessary.
5. **Stop at Phase End:** You MUST run the full test suite (`npm run test`) at the end of each phase and output the test results before moving to the next phase.

## Phase 1: Types and State Definition
**Goal:** Define the data structures for the new deformation controls.
1. Update relevant type definition files (e.g., in `src/types/`) to include a new interface for `DeformationSettings`:
   - `amplitude` (number)
   - `baseRadius` (number)
   - `sharpness` (number)
   - `colorIntensity` (number)
   - `smoothing` (number)
   - `resolution` (number)
   - `wireframe` (boolean)
2. Define sensible default values for these properties.
3. **TDD Checkpoint:** Write basic type-check tests or state-initialization tests. Ensure tests pass before proceeding.

## Phase 2: Shader and AmbiScene Integration
**Goal:** Wire the parameters into the Three.js rendering pipeline inside `src/visualizer/AmbiScene.ts` and `src/visualizer/shaders/sphereDeformation.ts`.
1. **Tests First:** Open `src/visualizer/AmbiScene.test.ts`. Write tests asserting that:
   - Calling a new method (e.g., `updateDeformationSettings(settings)`) updates the corresponding shader uniforms (`uDeformScale`, `uBaseRadius`, `uSharpness`, `uColorIntensity`).
   - Toggling the `wireframe` setting updates the Three.js material's `wireframe` property.
   - Changing the `resolution` setting correctly triggers a geometry rebuild for the sphere without memory leaks.
2. **Implementation:** - Add the necessary uniforms to the GLSL code in `src/visualizer/shaders/sphereDeformation.ts`.
   - Implement `updateDeformationSettings` in `src/visualizer/AmbiScene.ts`.
   - Implement the geometry rebuild logic in `AmbiScene.ts` to handle dynamic resolution changes (ensure old geometry is properly disposed).
   - Implement the temporal smoothing/decay logic for the audio data being passed to the deformation attributes.
3. **TDD Checkpoint:** Run the `AmbiScene.test.ts` suite. Fix any issues until all tests pass.

## Phase 3: UI Integration & Context-Aware Swapping
**Goal:** Expose the new controls in `src/components/VisualizerControls.tsx` and implement conditional rendering so only the relevant controls for the active mode are shown.
1. **Tests First:** Write/update tests for `VisualizerControls.tsx` to ensure:
   - When the active mode is "Sphere Deformation", the new Deformation sliders (Amplitude, Base Radius, Sharpness, Color Intensity, Smoothing, Resolution) and Wireframe toggle render.
   - When the active mode is "Volumetric", the existing Volumetric sliders render, and the Deformation sliders DO NOT render.
   - Interacting with the new inputs calls the appropriate state update callbacks.
2. **Implementation:**
   - Group the existing Volumetric controls into their own sub-container or render block.
   - Create a new sub-container or render block for the Sphere Deformation controls.
   - Use the existing visualization mode state (from PRP #45) to conditionally render only the active group of controls.
   - Ensure the new UI matches the existing styling and utilizes the universal polling system (`isDraggingSlider` flags) to prevent state-fighting.
3. **TDD Checkpoint:** Run UI component tests. Ensure all pass.

## Phase 4: App Wiring
**Goal:** Connect the UI state to `AmbiScene` in `src/App.tsx`.
1. **Implementation:** - Add React state for `deformationSettings` in `src/App.tsx`.
   - Pass the state and setter down to `VisualizerControls.tsx`.
   - Pass the state into the `AmbiScene` instance to ensure `AmbiScene` receives real-time updates when the sliders move.
2. **TDD Checkpoint:** Run the entire test suite (`npm run test`). All tests across the project must pass.

## Phase 5: Final Validation & User Handoff
**Goal:** Stop execution and request manual testing.
1. DO NOT proceed to make further unsolicited changes or start new tasks.
2. Present a summary of the implemented controls, the conditional rendering logic, and the results of the final test suite run.
3. **Mandatory Action:** Explicitly ask the user: "The implementation is complete and all tests are passing. Please start the development server (`npm run dev`), toggle between the Volumetric and Sphere Deformation views, and verify that the control panels swap correctly. Test the new sliders and wireframe toggle in Sphere mode to ensure they feel responsive. Let me know if any visual tuning is required."
