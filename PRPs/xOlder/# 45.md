
### PRP: Integrate Multi-Mode Visualization Architecture

**Objective:** Integrate the legacy sphere deformation code from `temp_legacy_viz` into the active project as a toggleable option alongside the current ray marching volumetrics.

**Context:**
We now have the original sphere deformation logic isolated in `temp_legacy_viz`. The goal is to refactor the visualization pipeline so the user can switch between "Volumetric (Ray Marching)" and "Deformation (Sphere)" at runtime via the UI.

**Step-by-Step Instructions:**

1. **Analyze the Deltas (No modifications yet):**
* Compare `temp_legacy_viz/src/visualizer/AmbiScene.ts` with the active `src/visualizer/AmbiScene.ts`. Note how the scene, camera, and renderer setup differ from the specific mesh/material implementations.
* Compare the legacy `RawCoefAnalyser.ts` with the active one. Determine if the active analyser provides the correct data format for the legacy sphere shaders, or if it needs to be updated to output dual data streams (one for volumetrics, one for sphere deformation).


2. **Refactor the Shader and Material Assets:**
* Copy the legacy shader logic from `temp_legacy_viz/src/visualizer/shaders/ambisonic.ts` into the active `src/visualizer/shaders/` directory. Rename it to something distinct (e.g., `sphereDeformation.ts`) to avoid conflicts with the ray marching shaders.


3. **Implement a Visualization Strategy in `AmbiScene.ts`:**
* Do not duplicate the Three.js boilerplate (Canvas, Renderer, Camera, Lights).
* Refactor `AmbiScene.ts` to act as a manager. It should instantiate *both* the ray marching mesh/material and the sphere deformation mesh/material.
* Implement a `setVisualizationMode(mode: 'volumetric' | 'sphere')` method in `AmbiScene.ts`.
* When the mode switches, safely swap which mesh is added to the active Three.js scene (ensure you properly hide or remove the inactive mesh to save resources, but you don't necessarily need to dispose of it unless memory becomes an issue).


4. **Wire the React UI:**
* Add a new state for `visualizationMode` in the top-level React application (likely `App.tsx`).
* Create a UI toggle (e.g., a dropdown or toggle switch) in the control panel to switch between "Volumetric" and "Sphere".
* Pass this state down to the visualization component so it calls the `setVisualizationMode` method in `AmbiScene.ts`.


5. **Verify Data Flow:**
* Ensure the `requestAnimationFrame` render loop passes the correct audio analysis data from `RawCoefAnalyser.ts` to the currently active material/shader.



**Definition of Done:**

* The application builds without errors.
* The UI contains a visible toggle for the visualization mode.
* The user can seamlessly switch between the new ray marching and the legacy sphere deformation in real-time.
* The `temp_legacy_viz` folder can be safely deleted once integration is verified.
