
> **Subject: Overhaul Transport Button Interaction States**
> We need to fix a critical UX issue with our transport buttons. Currently, the buttons lack distinct visual states for toggled/untoggled vs. mouse interactions. Because the "Hover" state and the "On/Selected" state share the same visual treatment, users cannot tell if a button is interactive, nor can they tell if they've successfully turned a button off while still hovering over it.
> Please update the component to support a two-dimensional state matrix. I need distinct visual treatments (e.g., changes in background color, icon color, opacity, or borders) for all of the following combinations:
> **Category 1: The "Off" States (Untoggled)**
> * **Default (Off):** The resting state.
> * **Hover (Off):** Mouse over. Must indicate clickability (e.g., slightly lighter/darker background).
> * **Pressed (Off):** The active click moment.
> 
> 
> **Category 2: The "On" States (Toggled)**
> * **Default (On):** The resting state when active. Must look distinctly "pressed in" or highlighted compared to *Default (Off)*.
> * **Hover (On):** Mouse over while the feature is active. **Crucial:** This *must* look different from both *Default (On)* and *Hover (Off)* so the user knows they are targeting an already-active button. (e.g., if the 'On' state is a bright blue background, the 'Hover (On)' state should be a slightly brighter or darker blue).
> * **Pressed (On):** The active click moment to turn it off.
> 
> 
> Please generate the design specs/code for these 6 distinct states so the user receives immediate visual feedback at every stage of interaction.
