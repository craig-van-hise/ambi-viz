# Product Requirements Prompt (PRP): UI Migration & Integration

## 1. Project Context & Objectives
The project UI is being replaced with a new design exported from AI Studio, located in `./temp_AI_Studio_UI/`. The objective is to migrate these new React components, styles, and animations into the main `src/` directory while reconnecting them to the existing Ambisonic audio engine, ESKF tracking, and Three.js visualizer backend.

## 2. Technical Decisions & Dependencies
* **New Stack Additions:** Tailwind CSS v4 (`@tailwindcss/vite`), Lucide React (`lucide-react`), and Motion (`motion`).
* **Source Path:** `./temp_AI_Studio_UI/`
* **Bidirectional Logic:** The agent MUST preserve the "Universal UI Sync" logic (Render Loop Polling) and the `isDraggingSlider` guard to prevent state-fighting between manual interaction and head-tracking.
* **Camera Hardening:** Ensure the Pitch clamping (±89.4°) and Origin Lock (0,0,0) logic are correctly wired into the new UI's slider inputs.

## 3. Implementation Phases

### Phase 0: Dependency & Configuration Sync
* **Objective:** Prepare the environment for the new UI requirements.
* **Instructions:**
    1. Compare the project's root `package.json` with the one in `./temp_AI_Studio_UI/`.
    2. Install missing dependencies: `motion`, `lucide-react`, and the Tailwind v4 ecosystem.
    3. Update `vite.config.ts` to include the `@tailwindcss/vite` plugin if required by the new design.
* **TDD Checkpoint:**
    * **Test Case 1:** Run `npm list motion lucide-react`; Assert all are present.
    * **AGENT INSTRUCTION:** "Confirm the dev server starts without configuration errors before moving to Phase 1."

### Phase 1: Structural Audit & Mapping
* **Objective:** Map new UI components to existing backend services.
* **Instructions:**
    1. Analyze the components in `./temp_AI_Studio_UI/`.
    2. Identify replacements for: `TransportControls`, `TrackQueue`, `VisualizerControls`, `ESKFTuningPanel`, and `CameraControlPanel`.
    3. Locate the new slider and button components; verify they support the necessary events (e.g., `onChange`, `onPointerDown`).
* **TDD Checkpoint:**
    * **Test Case 1:** Provide a mapping summary to the user (e.g., "New 'MediaBar' replaces 'TransportControls'").
    * **AGENT INSTRUCTION:** "Wait for user acknowledgment of the mapping before proceeding."

### Phase 2: Core Layout & Audio Wiring
* **Objective:** Replace `App.tsx` and restore audio transport functionality.
* **Instructions:**
    1. Update `App.tsx` with the new layout, ensuring the Three.js `<canvas>` container is preserved.
    2. Map the new UI's Play/Pause/Stop and Track selection to `AudioEngine.ts` methods.
    3. Re-implement the `stop() -> loadTrack() -> play()` sequence in the new Track Queue component.
* **TDD Checkpoint:**
    * **Test Case 1:** Click the new Play button; Assert `audioEngine.play()` is invoked.
    * **Test Case 2:** Double-click a track in the new UI; Assert the "loading" guard prevents rapid-click collisions.

### Phase 3: 3DOF Tracking & Visualization Bridge
* **Objective:** Reconnect head-tracking and manual camera sliders.
* **Instructions:**
    1. Bind the new Yaw/Pitch/Roll sliders to the `Orientation` state.
    2. Restore the logic that updates `camera.up` for Roll support and `camera.lookAt` for Gaze alignment.
    3. Ensure the new UI toggles correctly switch between **Volumetric Ray-Marching** and **Sphere Deformation** modes in `AmbiScene.ts`.
* **TDD Checkpoint:**
    * **Test Case 1:** Move the Pitch slider; Assert the 3D camera tilts and the value is clamped to ±89.4°.
    * **Test Case 2:** Enable Head-Tracking; Assert the new UI sliders move automatically to mirror the head movement.
