# Product Requirements Prompt (PRP) — [Status Marker] ✅

## 1. Project Context & Objectives
The onboarding tooltip for Step 2 ("Start Tracking") is being visually clipped at the edge of the sidebar. This is occurring because its parent container has an `overflow-y-auto` CSS property, which forces a hard clipping boundary on all child elements that extend beyond its box. The objective is to restructure the `ControlSidebar` layout so the tracking button (and its absolute-positioned tooltip) lives outside the scrolling panel region, preventing it from being cropped.

## 2. Technical Decisions & Dependencies
* **Target File:** `src/components/ControlSidebar.tsx`
* **Architectural Action:** Split the sidebar's internal layout into two distinct sections: 
  1. A static, non-scrolling top section containing the "Controls" header and the "Start Tracking" toggle.
  2. A flexible, scrolling bottom section containing all the expandable tuning panels.
* **Benefit:** This removes the tooltip from the `overflow` clipping context entirely, allowing it to render freely over the adjacent `MainViewer`. It also keeps the primary tracking action persistently visible while scrolling.

## 3. Implementation Phases
