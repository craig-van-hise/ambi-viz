# Product Requirements Prompt (PRP) — [Status Marker] ✅

## 1. Project Context & Objectives
The onboarding walkthrough successfully persists its completed state to `localStorage`, preventing it from showing on subsequent visits. However, there is currently no user-facing way to restart the tutorial if a user wants to review the instructions or if they accidentally dismissed it. We need to expose a "Restart Tutorial" action within the UI, specifically locating it in the `InfoModal`.

## 2. Technical Decisions & Dependencies
* **Target Files:** * `src/components/onboarding/OnboardingContext.tsx`
  * `src/components/InfoModal.tsx`
* **Architectural Action:** Expand the `OnboardingContext` to expose a `resetOnboarding()` function. This function will clear the specific `localStorage` key and reset the React state to `'HEADPHONES'`. 
* **UI Integration:** Add a subtle but accessible button at the bottom of the `InfoModal` to trigger this reset, which will immediately close the modal and start the walkthrough.

## 3. Implementation Phases

### Phase 1: Extend Context Logic — [Status Marker] ✅ Completed
* **Objective:** Create the state-reset function in the global context.
* **Instructions:**
  1. Open `src/components/onboarding/OnboardingContext.tsx`.
  2. Add a new function to the context value signature: `resetOnboarding: () => void`.
  3. Implement `resetOnboarding` inside the Provider:
     * It must remove the `localStorage` item (e.g., `localStorage.removeItem('ambiviz_onboarding_completed')`).
     * It must update the internal `currentStep` state back to `'HEADPHONES'`.
  4. Ensure this new function is exported via the context provider.
* **TDD Checkpoint:**
  * **Test Case 1:** [Given the state is 'COMPLETED', When `resetOnboarding()` is called, Assert that the `localStorage` key is removed and the state becomes 'HEADPHONES'.]
  * **Status Update:** "Transition Phase status to 🔵 Active. Implement the context extension. Update status to ✅ Completed before initiating subsequent phases."

### Phase 2: Add UI Trigger to InfoModal — [Status Marker] ✅ Completed
* **Objective:** Expose the reset function to the user via the Info Modal.
* **Instructions:**
  1. Open `src/components/InfoModal.tsx`.
  2. Import the `useOnboarding` hook (or equivalent `useContext` call) to access `resetOnboarding()`.
  3. At the bottom of the modal content (perhaps just below the Attribution table or as a footer action), add a new button.
  4. Style the button to look like a secondary or ghost action (e.g., standard padding, muted background like `bg-gray-800 hover:bg-gray-700`, text `Restart Walkthrough`).
  5. In the button's `onClick` handler, call `resetOnboarding()` and *also* call the function to close the `InfoModal` so the user can immediately see the Step 1 Headphone prompt.
* **TDD Checkpoint:**
  * **Test Case 1:** [Given the `InfoModal` is open, When the user clicks "Restart Walkthrough", Assert that the context reset function is called and the modal close function is called.]
  * **Status Update:** "Transition Phase status to 🔵 Active. Wire up the UI button and verify. Update status to ✅ Completed before initiating subsequent phases."
  * **User Verification:** "[USER VERIFICATION REQUIRED] Ensure you are currently in a 'COMPLETED' state (no tutorial visible). Open the Info Modal, scroll to the bottom, and click 'Restart Walkthrough'. Confirm the modal closes and the Step 1 Headphone prompt immediately appears."
