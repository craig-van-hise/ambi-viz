

### 🛠️ Agent Instruction Plan: Sync Head-Orientation Arrow with Inside View Projection

**Objective:** Correct the visual scaling and tracking of the head-orientation arrow (green arrow and shadow arrow) in the Inside View, ensuring it perfectly aligns with the custom equirectangular sound field coordinate system.

**Strategy:** Implement a custom `ShaderMaterial` for the arrow objects that utilizes the same aspect-corrected, non-linear spherical projection developed for the `sphereDeformation.ts` legacy shader.

#### Step 1: Create a New Shader Module for the Arrow

**File to create:** `src/visualizer/shaders/arrowShader.ts`

Create a new file containing the shader code tailored specifically for these 3D objects. (Note: We are not using the vertex displacement math, just the non-linear projection).

```typescript
// src/visualizer/shaders/arrowShader.ts

export const arrowVertexShader = `
uniform bool u_isInsideView;
uniform vec2 u_resolution;
uniform float u_fov;

varying vec2 vUv;
varying vec3 vNormal;
varying vec3 vViewPosition;

void main() {
    vUv = uv;
    vNormal = normalize(normalMatrix * normal);
    
    // We assume the arrow is already in a local position that
    // correctly reflects its orientation relative to the camera
    // (e.g., if head is forward, position.z is large negative).
    
    // Convert to view space (position relative to camera)
    vec4 viewPosition = modelViewMatrix * vec4(position, 1.0);
    vViewPosition = viewPosition.xyz;
    
    if (u_isInsideView) {
        // --- NON-LINEAR SPHERICAL PROJECTION (Inside View) ---
        
        // 1. Get the direction from the camera to the vertex in view space
        vec3 dir = normalize(viewPosition.xyz);
        
        // 2. Map direction to Spherical Angles (Yaw and Pitch)
        // In Three.js view space: -Z is forward, +X is right, +Y is up
        float yaw = atan(dir.x, -dir.z); 
        float pitch = asin(dir.y);
        
        // 3. Aspect Ratio and FOV Correction
        float aspect = u_resolution.x / u_resolution.y;
        float fovScale = (u_fov * 3.14159265 / 180.0) * 0.5;
        
        // 4. Map angles to Normalized Device Coordinates (NDC: -1.0 to 1.0)
        vec2 ndc = vec2(yaw / (fovScale * aspect), pitch / fovScale);
        
        // 5. DIRECT CLIP-SPACE OUTPUT (Bypassing perspective divide)
        // Set a safe depth of 0.5. We do not need the aggressive back-cull here
        // as the arrow is small and does not have a "back seam" stretching artifact.
        gl_Position = vec4(ndc, 0.5, 1.0);
        
    } else {
        // --- STANDARD PERSPECTIVE PROJECTION (Outside View) ---
        gl_Position = projectionMatrix * viewPosition;
    }
}
`;

export const arrowFragmentShader = `
uniform vec3 u_color;
varying vec3 vNormal;
varying vec3 vViewPosition;

void main() {
    // Basic diffuse lighting so the arrow has depth
    vec3 lightDir = normalize(vec3(0.5, 0.5, 1.0)); // Fixed light relative to view
    float light = max(dot(vNormal, lightDir), 0.2); // Add some ambient light
    
    // Special depth fade for 'shadow arrow' or 'shadow' effect if vViewPosition is far
    // (You can omit this if your shadow is just a separate solid object)
    
    gl_FragColor = vec4(u_color * light, 1.0);
}
`;

```

#### Step 2: Apply the Shader and Update Uniforms

**File to modify:** `src/visualizer/AmbiScene.ts`

1. **Locate the Arrow Initialization:** Find where the green arrow and shadow arrows are created (e.g., in the class constructor or `setupScene`). They are likely `THREE.ArrowHelper` objects or custom meshes.
2. **Replace Materials:** Create and assign the new custom shader materials. Assuming they are meshes:

```typescript
import { arrowVertexShader, arrowFragmentShader } from './shaders/arrowShader';

// ... inside initialization ...

// Define standard arrow uniforms (ensure state consistency with main shader)
const arrowUniforms = {
    u_isInsideView: { value: true },
    u_resolution: { value: new THREE.Vector2(window.innerWidth, window.innerHeight) },
    u_fov: { value: this.camera.fov },
    u_color: { value: new THREE.Color(0x00ff00) } // Green for main arrow
};

// Create the green arrow material
const greenArrowMaterial = new THREE.ShaderMaterial({
    uniforms: THREE.UniformsUtils.clone(arrowUniforms),
    vertexShader: arrowVertexShader,
    fragmentShader: arrowFragmentShader,
    transparent: true,
    depthTest: true
});

// Update the shadow arrow color uniform
arrowUniforms.u_color.value.set(0x000000); // Black for shadow
arrowUniforms.u_color.value.offsetHSL(0, 0, -0.2); // Make it slightly translucent gray
const shadowArrowMaterial = new THREE.ShaderMaterial({
    uniforms: THREE.UniformsUtils.clone(arrowUniforms),
    vertexShader: arrowVertexShader,
    fragmentShader: arrowFragmentShader,
    transparent: true,
    opacity: 0.5,
    depthTest: true
});

// Locate your existing arrow meshes or recreate them using these materials.
// If using THREE.ArrowHelper, you may need to dig into .children[0] (line) 
// and .children[1] (cone) and replace their materials individually.
// It is recommended to implement the orientation arrow as a custom mesh if it's not already.

// STORE REFERENCES for updating later
this.arrowMaterial = greenArrowMaterial;
this.shadowArrowMaterial = shadowArrowMaterial;

```

#### Step 3: Verification Constraints for Agents

* **Orientation Alignment:** Ensure that when the head tracking indicates $0^\circ$ (pointing "FRONT"), the arrow is center-screen. Turn the head exactly $90^\circ$ (pointing "RIGHT"). The green arrow should now visually align exactly with the "RIGHT" orientation label and the $90^\circ$ grid line. If they are out of sync, the hypothesis that standard perspective was compressing the arrow is confirmed.
* **Outside View Persistence:** When switching to "Outside View," the arrow must return to using standard perspective so it looks correct as a physical 3D object parented to the camera, consistent with how the overall sphere object looks.
