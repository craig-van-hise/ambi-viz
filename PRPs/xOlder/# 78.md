# Product Requirements Prompt (PRP) — [Status Marker] ✅

## 1. Project Context & Objectives
To reduce friction for first-time users experiencing 3DoF spatial audio, AmbiViz requires a lightweight, 3-step interactive onboarding walkthrough. The goal is to ensure users have the necessary hardware (headphones) and understand the two primary interactions required to experience the app: starting the tracking and playing the audio. 

Crucially, to prevent UX confusion, Step 2 ("Start Tracking") must not advance merely upon a button click, as the browser will intercept the user with a camera permission prompt. The walkthrough must wait until tracking is successfully initialized before proceeding to Step 3.

## 2. Technical Decisions & Dependencies
* **State Management:** Implement a React Context (`OnboardingContext`) to manage the current step (`'HEADPHONES' | 'TRACKING' | 'PLAYBACK' | 'COMPLETED'`).
* **Persistence:** Bind the `'COMPLETED'` state to `localStorage` (`ambiviz_onboarding_completed`) so returning users bypass the tutorial.
* **Animation:** Utilize the existing `motion` (framer-motion) dependency to create smooth, pulsing arrows that direct the user's attention.
* **Event Delegation Shift:** Do not bind Step 2 advancement to the "Start Tracking" button's `onClick`. Instead, use a reactive `useEffect` to observe the global `isTracking` boolean state to ensure the camera is actually active.
* **Component Strategy:** * Step 1 (Headphones): A centered, blocking modal overlay.
  * Steps 2 & 3 (Tracking/Play): A reusable, absolutely positioned `<OnboardingTooltip>` injected near the target elements in `ControlSidebar` and `TransportControls`.

## 3. Implementation Phases

### Phase 1: Context & Persistence Setup — [Status Marker] ✅ Completed
* **Objective:** Establish the global state machine for the onboarding flow.
* **Instructions:**
  1. Create `src/components/onboarding/OnboardingContext.tsx`.
  2. Define the context to hold `currentStep` and a function `advanceStep()`.
  3. Initialize the state by checking `localStorage` for `ambiviz_onboarding_completed`. If true, set state to `'COMPLETED'`. Otherwise, set to `'HEADPHONES'`.
  4. Wrap the main application tree in `App.tsx` with the new `<OnboardingProvider>`.
* **TDD Checkpoint:**
  * **Test Case 1:** [Given a first-time load, When the provider mounts, Assert the state initializes to 'HEADPHONES'.]
  * **Test Case 2:** [Given the user has completed onboarding before, When the provider mounts, Assert the state initializes to 'COMPLETED'.]
  * **Status Update:** "Transition Phase status to 🔵 Active. Implement the Context Provider and verify state via React DevTools. Update status to ✅ Completed before initiating subsequent phases."

### Phase 2: Step 1 - The Headphone Gate — [Status Marker] ✅ Completed
* **Objective:** Ensure the user physically puts on headphones before interacting with the app.
* **Instructions:**
  1. Create `src/components/onboarding/HeadphonePrompt.tsx`.
  2. This should be a full-screen, semi-transparent overlay (using standard Tailwind backdrop-blur/z-index utilities) containing a focused message: "Step 1: Put on your headphones. 3D spatial audio requires headphones to work."
  3. Include a prominent confirmation button: "I'm wearing headphones".
  4. Hook the button's `onClick` to trigger `advanceStep()` (moving the state to `'TRACKING'`).
  5. Conditionally render this component in `App.tsx` only when `currentStep === 'HEADPHONES'`.
* **TDD Checkpoint:**
  * **Test Case 1:** [Given state is 'HEADPHONES', When the UI renders, Assert the HeadphonePrompt is visible.]
  * **Test Case 2:** [Given the user clicks "I'm wearing headphones", When the event fires, Assert the Context state transitions to 'TRACKING' and the prompt unmounts.]
  * **Status Update:** "Transition Phase status to 🔵 Active. Build and verify the component. Update status to ✅ Completed before initiating subsequent phases."

### Phase 3: Steps 2 & 3 - Tooltips & Reactive Triggers — [Status Marker] ✅ Completed
* **Objective:** Guide the user to the Tracking and Playback controls using animated pointers, advancing only when actual states change.
* **Instructions:**
  1. Create a reusable UI component: `src/components/onboarding/AnimatedPointer.tsx` utilizing `framer-motion` for a gentle pulsing/bouncing effect (e.g., looping translation).
  2. **Step 2 (Tracking):** Open `src/components/ControlSidebar.tsx` (or wherever the tracking toggle resides). 
     * Read the `OnboardingContext`. If `currentStep === 'TRACKING'`, render the `<AnimatedPointer text="Step 2: Start Tracking" direction="right" />` absolutely positioned to point at the tracking button.
     * **Crucial Logic:** Do *not* add `advanceStep()` to the button click. Instead, implement a `useEffect` that listens to `isTracking`:
       ```javascript
       useEffect(() => {
         if (currentStep === 'TRACKING' && isTracking) { advanceStep(); }
       }, [currentStep, isTracking, advanceStep]);
       ```
  3. **Step 3 (Playback):** Open `src/components/TransportControls.tsx`. If `currentStep === 'PLAYBACK'`, render the `<AnimatedPointer text="Step 3: Press Play" direction="down" />` pointing to the main Play button. Hook the Play button's `onClick` to call `advanceStep()` (moving state to `'COMPLETED'`), which also writes to `localStorage`.
* **TDD Checkpoint:**
  * **Test Case 1:** [Given state is 'TRACKING' and `isTracking` is false, When the user clicks "Start Tracking", Assert that the state remains 'TRACKING' (simulating pending camera permission).]
  * **Test Case 2:** [Given state is 'TRACKING', When `isTracking` state changes to true, Assert that the state advances to 'PLAYBACK'.]
  * **Test Case 3:** [Given state is 'PLAYBACK', When the user clicks Play, Assert the state updates to 'COMPLETED' and all tooltips disappear.]
  * **Status Update:** "Transition Phase status to 🔵 Active. Implement the tooltips and interaction triggers. Update status to ✅ Completed before initiating subsequent phases."
  * **User Verification:** "[USER VERIFICATION REQUIRED] Clear browser site settings to force a fresh camera permission prompt. Start the app, click 'Start Tracking', and verify that the Step 2 tooltip remains visible *until* you click 'Allow' and the camera light turns on. Then verify Step 3."
