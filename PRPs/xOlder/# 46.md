# Product Requirements Prompt (PRP)

## 1. Project Context & Objectives
The goal of this PRP is to extend the `AmbiViz` audio ingestion pipeline to support the `.opus` file format. Currently, the system supports `.wav`, `.ambix`, `.ogg`, and `.iamf` files. This task involves updating file filtering, validation logic, and UI labeling to ensure `.opus` files are treated as valid Ambisonic sources.

## 2. Technical Decisions & Dependencies
* **MIME Type Support:** The application must recognize `audio/opus`.
* **File Extension Support:** The application must explicitly allow `.opus` in individual file selectors and recursive folder scanning.
* **Audio Decoding:** Use `BaseAudioContext.decodeAudioData()`, which natively supports Opus in modern browsers.
* **Ambisonic Mapping:** `.opus` files should be treated with the same channel mapping assumptions as `.ogg` or `.ambix` (Order 1-3 ACN/SN3D).

## 3. Implementation Phases

### Phase 1: Update File Validation & Constants
* **Objective:** Ensure the UI and file processing utilities recognize `.opus` files.
* **Instructions:**
    1.  Locate the file validation logic (likely `src/components/FileLoader.tsx` or `src/utils/`).
    2.  Add `.opus` to the `SUPPORTED_EXTENSIONS` array.
    3.  Update the `accept` attribute in `<input type="file">` to include `.opus` and `audio/opus`.
    4.  Update folder scanning logic to include `.opus` in its filter.
* **TDD Checkpoint:**
