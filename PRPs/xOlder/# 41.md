
# PRP #41: Volumetric Ray-Marching Visual Controls

## 1. Objective

Implement a suite of advanced visual parameters to control the dynamic range, clarity, and temporal response of the volumetric ray-marched Ambisonic visualizer. This implementation must replace the monolithic "Gain" concept with granular shader uniforms and expose them via a React UI panel, strictly following Test-Driven Development (TDD).

## 2. Target Parameters

1. **Density Threshold (Fog Gate):** A hard floor for density to strip away ambient room noise.
2. **Density vs. Emission Multipliers:** Decouple physical volume thickness from glowing heat brightness.
3. **Heatmap Shift (Knee):** Shift the 1D color transfer function to tame blown-out signals.
4. **Edge Falloff (Feathering):** A power function applied to density to sharpen or soften the spatial lobes.
5. **Temporal Dissipation:** Frame-buffer feedback (ping-pong FBOs) to create lingering smoke trails and smooth erratic flickering.

## 3. Architecture Context

* **Target Files:** `src/visualizer/AmbiScene.ts`, `src/visualizer/shaders/*`, `src/components/` (new or existing panel), `src/utils/persistence.ts`.
* **Engine:** Three.js (WebGL2) / React (Vite).
* **Note:** Prioritize singularity protection and strict type coercion for all slider inputs to prevent WebGL context crashes (adhering to the hardening standards established in PRP #20).

## 4. Execution Phases (TDD Enforced)

### Phase 1: State & Uniform Architecture (TypeScript)

**Goal:** Define the data structures, update the Three.js material definitions, and handle state management before touching GLSL or React.

1. **Actions:**
* Update `AmbiScene.ts` to include the new parameters in the `uniforms` object of your custom `ShaderMaterial`.
* Implement getter/setter methods in `AmbiScene` with strict type coercion (e.g., `Number(val)`) to prevent `NaN` values crashing the shader.
* Set up the Framebuffer Object (FBO) ping-pong logic in `AmbiScene.ts` required for the Temporal Dissipation effect.


2. **TDD Requirements:**
* Write unit tests in `src/visualizer/AmbiScene.test.ts` to verify that updating these parameters correctly modifies the underlying material uniforms.
* Test the bounds clamping for each parameter.


3. **🛑 Phase 1 Checkpoint:** Run Vitest. Do not proceed to Phase 2 until all `AmbiScene` tests pass.

### Phase 2: Shader Implementation (GLSL)

**Goal:** Integrate the new uniforms into the volumetric ray-marching loop.

1. **Actions:**
* Update `src/visualizer/shaders/*` (vertex/fragment).
* **Threshold & Falloff:** In the ray loop, implement `if (energy < u_densityThreshold) continue;` or smoothly step the density. Apply `pow(energy, u_edgeFalloff)` to shape the lobe.
* **Density vs Emission:** Multiply the accumulated alpha by `u_densityMult` and the accumulated color by `u_emissionMult`.
* **Heatmap Shift:** Add `u_heatmapKnee` as an offset/scale to the UV coordinate used to sample your color ramp/transfer function.
* **Temporal Dissipation:** Sample `u_previousFrame` texture, apply `u_dissipationRate`, and blend it with the current accumulated ray-march output.


2. **TDD Requirements:**
* Validate shader compilation.
* Ensure the addition of the FBO/Ping-Pong logic does not break the 3DOF Orientation Matrix and hard origin lock established in PRP #25.


3. **🛑 Phase 2 Checkpoint:** Render a test scene. Verify no WebGL "Black Screen" context losses occur when parameters are pushed to their extremes. Do not proceed until the shader compiles and runs stably.

### Phase 3: UI Integration (React)

**Goal:** Expose the parameters to the user via a dedicated tuning panel.

1. **Actions:**
* Create a new component (e.g., `src/components/VisualizerTuningPanel.tsx`) or integrate into the existing UI.
* Create 6 sliders mapping to the 5 parameters (Density and Emission get their own).
* Implement throttled polling or direct event updates to sync the React state with `AmbiScene` (utilizing the universal UI sync pattern from PRP #22).
* Integrate `src/utils/persistence.ts` to save and load these specific visualizer settings to `localStorage`.


2. **TDD Requirements:**
* Write component tests using React Testing Library to verify slider rendering, user interaction, and boundary value inputs.
* Test `localStorage` hydration to ensure parameters survive a page reload.


3. **🛑 Phase 3 Checkpoint:** Run Vitest UI tests. Do not proceed until all component and persistence tests pass.

### Phase 4: Full Pipeline Synchronization

**Goal:** Ensure the React UI correctly drives the GLSL shader in real-time.

1. **Actions:**
* Mount the `VisualizerTuningPanel` in `App.tsx`.
* Wire the React state changes to the `AmbiScene` setter methods created in Phase 1.


2. **TDD Requirements:**
* Perform an end-to-end integration test. Play a known Ambisonic test file (`test.wav`).
* Verify that aggressively scrubbing the sliders does not cause frame drops or state-fighting (verifying the `isDraggingSlider` guards).


3. **🛑 Phase 4 Checkpoint:** Final visual confirmation. All 5 parameters must demonstrably affect the ray-marched volume without breaking the audio spatialization or predictive head tracking.
