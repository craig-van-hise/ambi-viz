
# PRP #29: Volumetric Ray-Marching Bounding Sphere Intersection Fix

## 1. Objective

Fix the WebGL ray-marching bug where the Ambisonic volumetric visualization disappears when the outside camera is moved far away or positioned at extreme grazing angles. The fix requires implementing a Bounding Sphere Intersection algorithm to fast-forward the ray to the volume boundary, alongside expanding the ray's maximum travel distance parameters. This must be executed using strict Test-Driven Development (TDD) to ensure it does not break the existing "Inside View" origin locks.

## 2. Bug Context & Technical Strategy

Currently, the ray marcher in `src/visualizer/shaders/ambisonic.ts` begins stepping exactly at the camera's origin (`t = 0.1`) and maxes out at `32` steps of `0.1` units. This gives the ray a maximum travel distance of 3.2 units. If the camera is moved further than 3.2 units away from the audio volume, the `for` loop exhausts its steps entirely in empty space and renders nothing.

The strategy is to:

1. Increase `MAX_STEPS` and `MAX_DIST` to allow full volume traversal.
2. Use quadratic ray-sphere intersection math to find exactly where the camera's ray hits the `6.0` radius bounding sphere.
3. Fast-forward the starting step `t` to that intersection point, eliminating wasted steps in empty space.

## 3. Architecture Context

* **Target File:** `src/visualizer/shaders/ambisonic.ts`.
* **Engine:** Three.js (WebGL2) custom `ShaderMaterial`.
* **Constraint:** The fix must preserve the `DIRECTION-ONCE OPTIMIZATION` (`computeDirectionalEnergy`) and not interfere with the Inside View logic where the camera sits at `(0,0,0)`.

## 4. Execution Phases (TDD Enforced)

### Phase 1: Shader Constants Expansion

**Goal:** Increase the fundamental limits of the ray loop to allow it to cross the entire 12-unit diameter of the sound field.

1. **Actions:**
* In `src/visualizer/shaders/ambisonic.ts`, locate the raymarching constants.
* Update `MAX_STEPS` from `32` to `64`.
* Update `STEP_SIZE` from `0.1` to `0.15`.
* Update `MAX_DIST` from `10.0` to `30.0`.


2. **TDD Requirements:**
* Compile the shader.
* Run the Vite development server and ensure no syntax errors are thrown by the WebGL compiler.


3. **🛑 Phase 1 Checkpoint:** Do not proceed until the constants are updated and the application renders without context loss.

### Phase 2: Bounding Sphere Intersection Math

**Goal:** Implement the mathematical fast-forward so rays fired from far away jump immediately to the edge of the volume.

1. **Actions:**
* In `ambisonic.ts`, locate the variable initialization right before the `for` loop: `float t = 0.1;`.
* Replace it with the following Bounding Sphere Intersection logic (assuming a bounding radius of `6.0` which squares to `36.0`):
```glsl
// --- BOUNDING SPHERE INTERSECTION ---
float b = dot(rayOrigin, rayDir);
float c = dot(rayOrigin, rayOrigin) - 36.0; 
float h = b * b - c;

// Fast-forward 't' to the entry point. 
// If inside the sphere, max(0.1, ...) keeps it safely in front of the camera.
float tEnter = max(0.1, -b - sqrt(max(0.0, h))); 
float t = tEnter;
// ------------------------------------

```




2. **TDD Requirements:**
* Verify that this math is inserted *after* `closestDist` is calculated but *before* the `for (int i = 0; i < MAX_STEPS; i++)` loop begins.


3. **🛑 Phase 2 Checkpoint:** Render the application. The visualizer must compile successfully.

### Phase 3: Integration & Edge-Case Verification

**Goal:** Prove the fix works dynamically for both Inside View and extreme Outside View scenarios.

1. **Actions:**
* Launch the application and load `test.wav`.
* Toggle the camera to **Outside View**.
* Pull the zoom slider out to extreme distances (e.g., `Z = 20.0` or higher).
* Orbit the camera to view from directly above (top-down) and directly below (grazing angles).


2. **TDD Requirements:**
* **Test A (Distance):** Visualizer clouds must remain fully visible and correctly rendered regardless of how far back the camera is pulled.
* **Test B (Angles):** Visualizer clouds must not clip or disappear when viewed from steep angles.
* **Test C (Inside View Check):** Toggle back to Inside View. Ensure the `max(0.1, ...)` clamp prevents the camera from seeing inside its own clipping plane, and that the origin lock `(0,0,0)` still functions flawlessly.


3. **🛑 Phase 3 Checkpoint:** Final visual confirmation. The volumetric clouds must maintain perfect stability from all distances and angles.
