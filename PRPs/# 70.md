
### 🎯 Objective

Add native support for loading and decoding **BW64 (Broadcast Wave 64-bit)** audio files to the AmbiViz project.

### 🧠 Context & Problem Statement

The application currently handles standard audio formats via the browser's native `AudioContext.decodeAudioData()`. However, the Web Audio API does not natively support BW64 files because it chokes on the `BW64` magic bytes and the `ds64` (64-bit data size) chunk.

To solve this, we need to bypass the native decoder for `.bw64` files, manually parse the `ArrayBuffer` to extract the PCM data, and construct a standard `AudioBuffer` to feed into the existing OBR pipeline.

---

### 📋 Implementation Tasks

**1. Update the UI Dropzone**

* **Target File:** `src/components/FileLoader.tsx`
* **Action:** Update the accepted file types configuration to include `.bw64` extensions, ensuring the drag-and-drop interface allows the user to load these files.

**2. Create the BW64 Demuxer Utility**

* **Target File:** Create a new file, e.g., `src/audio/BW64Parser.ts`.
* **Action:** Write a class or utility function that takes an `ArrayBuffer` and an `AudioContext` as arguments, and returns a Promise that resolves to an `AudioBuffer`.
* **Parsing Logic Requirements:**
* Read the first 4 bytes to verify the `BW64` chunk ID.
* Iterate through the RIFF chunks to find `fmt ` (for sample rate, bit depth, channel count), `ds64` (to validate the 64-bit chunk sizes), and `data` (the raw PCM payload).
* Extract the raw PCM data. You must handle the conversion of the raw bytes (e.g., Int16, Int24, or Float32) into a standard normalized `Float32Array`.
* Use `AudioContext.createBuffer()` to create the empty buffer, and use `copyToChannel()` to populate the channels sequentially from the interleaved PCM data.



**3. Intercept & Route in the Audio Engine**

* **Target File:** `src/audio/AudioEngine.ts`
* **Action:** Locate the method responsible for loading and decoding the file buffer.
* **Logic Update:** Implement a conditional check based on the file extension or the first 4 bytes of the ArrayBuffer.
* If standard format (e.g., `.wav`, `.opus`, `.iamf`), route to the existing `audioContext.decodeAudioData()`.
* If `.bw64`, route the `ArrayBuffer` to the new `BW64Parser.ts` utility.



**4. Feed the OBR Pipeline**

* **Target Files:** `src/audio/AudioEngine.ts` and `src/audio/OBRDecoder.ts`
* **Action:** Ensure that the manually constructed `AudioBuffer` returned by `BW64Parser` seamlessly replaces the natively decoded buffer. It must flow into the `OBRDecoder` and the visualizer nodes without requiring changes to those downstream components.

### ⚠️ Constraints & Edge Cases

* **Channel Ordering:** Assume standard ACN/SN3D sequential channel ordering for now.
* **Metadata:** BW64 files often contain an `axml` chunk for Audio Definition Model (ADM) metadata. For this iteration, **ignore the `axml` chunk**. We are only concerned with extracting the sequential PCM audio data.
* **Performance:** The PCM extraction and Float32 conversion involve heavy array manipulation. Ensure the loop is optimized (e.g., using `DataView` efficiently) so it doesn't block the main thread excessively, or consider moving the parsing logic to a Web Worker if the files are massive.
