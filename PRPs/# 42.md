# PRP #42: Visualizer Controls Consolidation & Tooltip Integration

## 1. Objective

Refactor the visualizer UI by renaming the "Visualizer Tuning" card to "Visualizer Controls" and migrating the isolated "Zoom" and "Gain" sliders into this unified panel. Additionally, implement descriptive tooltips for every control in this panel to improve user comprehension of the ray-marching parameters. This must follow Test-Driven Development (TDD) to ensure UI state sync is maintained.

## 2. Target UI Structure & Tooltip Copy

The `VisualizerControls` panel must render the sliders in the exact order below, utilizing a standard Tooltip component (e.g., native title attributes, CSS tooltips, or a UI library component if already present in the project).

1. **Zoom:** "Adjusts the camera's field of view and proximity within the 3D ambisonic scene."
2. **Gain:** "Scales the raw Ambisonic audio energy before it enters the visual ray-marching pipeline."
3. **Density Threshold (Fog Gate):** "Sets the minimum audio energy required to render a cloud. Increase this to hide background room noise."
4. **Density Multiplier (Thickness):** "Controls the physical thickness and opacity of the volumetric audio clouds."
5. **Emission Multiplier (Brightness):** "Controls the glowing heat and brightness of the volume independently of its thickness."
6. **Heatmap Shift (Knee):** "Shifts the color transfer function to prevent loud transient sounds from blowing out the visualizer into solid white."
7. **Edge Falloff (Feathering):** "Adjusts the geometric sharpness of the spatial audio lobes. Higher values create tighter, more focused clouds."
8. **Temporal Dissipation:** "Controls how slowly the visual energy fades over time, creating lingering smoke trails that smooth out erratic flickering."

## 3. Architecture Context

* **Target Files:** `src/components/VisualizerTuningPanel.tsx` (to be renamed), `src/App.tsx` (to remove isolated controls), `src/components/` (for Tooltip implementation).
* **Engine:** React (Vite).
* **Note:** The Zoom slider and Gain slider already exist. Their underlying state management and rendering logic must be preserved during the move.

---

## 4. Execution Phases (TDD Enforced)

### Phase 1: Component Refactoring & Migration

**Goal:** Rename the existing panel and cleanly move the Gain and Zoom controls inside it without breaking their state connections.

1. **Actions:**
* Rename `VisualizerTuningPanel.tsx` to `VisualizerControls.tsx` (update imports across the app).
* Relocate the UI elements and state bindings for "Zoom" and "Gain" from `App.tsx` (or their current location) to the top of the `VisualizerControls` component.


2. **TDD Requirements:**
* Update component tests to reflect the new name `VisualizerControls`.
* Write a test asserting that Zoom and Gain render correctly at the top of the new panel.


3. **🛑 Phase 1 Checkpoint:** Run Vitest. Ensure the app compiles, the component renders, and the Zoom/Gain sliders still correctly manipulate the 3D scene.

### Phase 2: Tooltip Implementation Strategy

**Goal:** Establish a reusable tooltip wrapper for the sliders if one does not already exist.

1. **Actions:**
* Create a simple, accessible `Tooltip` wrapper component (or extend the existing slider component to accept a `tooltip` prop).
* Ensure the tooltip is triggered on hover/focus and does not disrupt the layout or slider dragging mechanics (respecting the `isDraggingSlider` flag logic).


2. **TDD Requirements:**
* Write a unit test for the Tooltip component ensuring it renders its children and displays the text layer on `onMouseEnter` or `onFocus`.


3. **🛑 Phase 2 Checkpoint:** Run Vitest. Do not proceed until the Tooltip logic is proven isolated and stable.

### Phase 3: Application & Styling

**Goal:** Apply the tooltips to the consolidated list of controls.

1. **Actions:**
* Map the exact copy provided in Section 2 to the corresponding sliders in `VisualizerControls.tsx`.
* Apply consistent CSS (e.g., via `App.css` or Tailwind/styled-components depending on project setup) so the tooltips are readable, correctly z-indexed over the WebGL canvas, and positioned logically.


2. **TDD Requirements:**
* Update the integration tests for `VisualizerControls` to assert that every single control contains the expected tooltip text string in the DOM.


3. **🛑 Phase 3 Checkpoint:** Run Vitest UI tests. All tooltips must be present and accounted for.

### Phase 4: Full Pipeline Verification

**Goal:** Ensure the UI refactor did not introduce regressions to the universal polling or render loop sync.

1. **Actions:**
* Perform a manual or automated end-to-end check.


2. **TDD Requirements:**
* Verify that hovering to read a tooltip while audio is playing does not cause stuttering.
* Verify that clicking and dragging the migrated Zoom and Gain sliders still respects the bidirectional sync rules established in earlier PRPs.


3. **🛑 Phase 4 Checkpoint:** Final visual confirmation. The UI should consist of a single, clean "Visualizer Controls" card with all 8 parameters correctly ordered and fully documented via tooltips.
