
### PRP: Salvage Legacy Sphere Deformation Visualization

**Objective:** Isolate and extract the original "sphere deformation" visualization code from the repository's initial commit. Place these files in a dedicated temporary folder in the project root so they can be analyzed and reintegrated as a toggleable visualization option in a future step.

**Context:**
The project recently updated its visualization engine to use ray marching volumetrics, which overwrote the original sphere deformation method. We want to recover the exact state of the Three.js scene and shaders from the very first commit without altering the current working directory's state.

**Step-by-Step Instructions:**

1. **Create a Temporary Directory:**
* Create a new folder in the project root called `temp_legacy_viz`.
* *Constraint:* Ensure this folder is added to `.gitignore` so we don't accidentally commit these duplicate files during the analysis phase.


2. **Identify the Initial Commit:**
* Use Git commands (e.g., `git rev-list --max-parents=0 HEAD` or `git log --reverse`) to find the hash of the very first commit in this repository where the sphere deformation logic was originally implemented.


3. **Locate the Target Files:**
* Inspect the tree of that initial commit. The files responsible for the sphere deformation are likely located in:
* `src/visualizer/AmbiScene.ts` (or the equivalent Three.js setup file from that time).
* `src/visualizer/shaders/` (any `.glsl`, `.vert`, or `.frag` files that existed in that commit).
* `src/audio/RawCoefAnalyser.ts` (if it existed and contained specific logic for formatting data for the sphere).




4. **Extract the Files Safely:**
* **CRITICAL:** Do NOT run `git checkout <commit>` in a way that alters the current working tree.
* Instead, use `git show <commit_hash>:<file_path> > temp_legacy_viz/<file_name>` (or a similar safe extraction method) to copy the contents of those specific historical files directly into the `temp_legacy_viz` folder.
* Maintain the folder structure inside `temp_legacy_viz` if it helps with readability (e.g., `temp_legacy_viz/visualizer/shaders/`).


5. **Verify and Document:**
* Verify that the files have been successfully copied into `temp_legacy_viz`.
* Create a brief `README-legacy-viz.md` inside `temp_legacy_viz` documenting the commit hash these files were pulled from and listing the files that were extracted.



**Definition of Done:**

* A `temp_legacy_viz` folder exists in the project root.
* The folder contains the `AmbiScene.ts` (or equivalent) and shader files exactly as they were in the initial commit.
* The current project files remain completely untouched and the project still builds and runs the current ray marching visualization.
